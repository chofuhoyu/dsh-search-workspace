# dsh-search-workspace

给 DeepSeek Harness 的工作区加搜索：**左侧栏的搜索框现在同时过滤工作区**（按名称或路径），并让**新会话的工作区选择**也能直接搜索。

工作区多了以后，原来的搜索只能找到会话，找不到工作区；本插件替换左侧栏的浏览区，让同一个搜索框同时覆盖工作区、会话标题和会话内容。

## 安装

在 DeepSeek Harness 的「插件」页点击「添加插件」，填入：

```text
github:chofuhoyu/dsh-search-workspace
```

也可以直接用 CLI 安装到目标 profile：

```sh
dsh plugin --profile desktop add github:chofuhoyu/dsh-search-workspace
```

安装后刷新 Web 页面。

## 用法

### 左侧栏

搜索框（放大镜）展开后输入：

- 工作区名称或路径命中时，先列出「匹配的工作区」，展开显示该工作区下的会话；
- 会话标题命中时，列出「匹配的会话」；
- 会话内容命中时，同样出现在「匹配的会话」里，并显示内容摘要；
- 空格分隔多个词时，每个词都要出现在工作区名称/路径或会话标题中；
- 清空搜索恢复工作区树。

日常操作保持原样：

- 点击工作区行展开/收起；行尾「新会话」按钮在该工作区新建会话；
- 点击会话行打开；会话行尾「…」打开原生的会话菜单（重命名、置顶、归档、分叉、复制 Session ID 等）；
- 工作区行尾「…」提供重命名和删除；
- 顶部「＋」添加工作区；滑块菜单可切换「隐藏/显示已归档」和「手动/最近更新」排序。

快捷键：`Cmd/Ctrl + Shift + K` 打开（或从侧栏收起状态展开）搜索框并聚焦。

> 原生 `Cmd/Ctrl + K` 的「搜索会话」命令仍由原生插件注册，但它驱动的原生浏览器已被本插件遮蔽，因此这个旧快捷键在替换后不再有可见效果。请使用上面的新快捷键，或直接点击搜索框。

### 新会话的工作区选择

点击新会话页面的工作区胶囊（文件夹图标 + 当前工作区名）后，弹出的列表顶部有搜索框：

- 输入即筛选，`↑` / `↓` 选择，`Enter` 确认，`Esc` 关闭；
- 直接点击仍然保持原来的选择行为；
- 名称重复的工作区显示足以区分的路径后缀；
- 底部「添加工作区…」保留，仍会打开原生目录选择器，并把这个目录注册为工作区。

## 设计说明

左侧栏的 `sidebar.workspaces` 是单占位槽，原生 `ui-workspace` 仍负责 `uiWorkspace` 服务、会话右键菜单、重命名/归档弹窗、通知和目录选择流。本插件以 `priority: -1` 遮蔽它的浏览器组件，但**不声明该槽的子槽**（子槽仍由原生注册声明），因此：

- 原生服务、会话菜单、弹窗和目录选择器继续工作；
- 本插件自己渲染工作区行和会话行，会话行尾的「…」直接复用原生 `contextMenu.button` 工厂和原生会话菜单；
- 工作区的重命名/删除由本插件自己的行菜单和弹窗提供。

界面组件（`Menu`、`Modal`、`Input`、`Button`、`Tooltip`、图标）复用 Harness 自带的
`@deepseek-ai/dsh-client-ui-primitives`，样式只使用 `--dsw-*` 主题 token 和侧栏布局变量。

## 与原生浏览器的差异

0.0.1 替换了整个浏览区，因此以下原生行为暂时没有逐项复刻：

- 会话行悬停的置顶/归档快捷按钮、计划任务标记、悬停卡片；这些动作仍可从会话行尾「…」菜单使用；
- 拖拽调整工作区或会话顺序；
- 工作区分组方式（按工作区 / 工作区树 / 单列表）切换；
- 工作区嵌套（按父目录嵌套）显示；
- 长标题悬停滚动。

会话内容搜索、归档筛选和按最近更新排序已保留。后续版本会按需要补齐。

## 配置

没有插件配置。快捷键可以在「设置 → 通用设置 → 快捷键」里改键；命令名是「查找工作区」
（`workspace.search`）。

## 验证

离线检查：

```sh
node scripts/check.mjs
```

它会在 Node `vm` 中按客户端模块加载器的形式执行 `client.js`，然后对假的 Client context 运行
`apply`，断言：

- 左侧栏浏览器与新会话选择器都以 `priority: -1` 遮蔽原生项，且不声明子槽；
- 快捷键命令的解析结果与搜索请求；
- 浏览器注入的打开/新建/添加/重命名/删除/搜索回调；
- 浏览器在宽栏和窄栏下的渲染、搜索匹配、会话可见性、置顶/归档排序和路径后缀；
- 客户端包只依赖 React 与 Harness 自带的 UI 基础组件，且样式没有字面色值。

这项检查不替代在真实 Harness 里安装并查看界面。
